# 공급업체 마스터 (CAP)

흩어져 있던 공급업체 정보를 **마스터 한 곳**에서 관리하고, 바뀐 값을 **진행 중 계약에 안전하게 반영**하는 서비스입니다.

## 왜 만들었나
- 계약마다 거래처 이름·계좌를 직접 입력해서, 같은 업체가 계약마다 다르게 적혀 있었습니다.
- 업체 계좌가 바뀌면 진행 중 계약을 하나씩 찾아 고쳐야 했고, 누가 언제 바꿨는지 남지 않았습니다.
- 공급업체 코드 없이 이름으로만 이어진 과거 계약이 많아 마스터와 연결할 방법이 필요했습니다.

## 설계
| 기능 | 내용 |
|---|---|
| 목록·상세 | 화면이 한 번에 필요한 묶음(목록 + 상태별 건수 / 상세 + 계약 + 이력)을 함수 하나로 반환 |
| 저장 미리보기 | 바뀐 칸, 반영될 진행 중 계약, 거래 상태 악화 경고를 **저장 전에** 보여 줌 |
| 저장 | 신규는 채번 후 등록, 수정은 마스터 → (계약 복사 칸이 바뀐 경우만) 진행 중 계약 반영 → 이력 |
| 변경 이력 | 칸 하나가 한 줄, 같은 저장은 `batchId`로 묶고 반영된 계약 수까지 기록 |
| 기존 계약 연결 | 코드 없는 계약을 사업자번호(없으면 이름)로 묶어 마스터에 등록·연결, `apply=false`면 미리보기 |
| 권한 | 조회는 로그인 사용자 전체, 쓰기는 담당 조직(하위 부서 포함)과 권한 관리자 → [cap-authz](../cap-authz) |

## 신경 쓴 부분
- **수정 시각이 없는 테이블의 동시성 제어**: 원장이 기존 시스템 테이블이라 `modifiedAt`이 없습니다. 칸 값 전체를 해시한 `stamp`를 상세 조회 때 내려주고, 저장 때 다시 계산해 다르면 409로 막습니다(낙관적 잠금).
- **반영 범위를 좁게**: 계약에 복사되는 칸(업체명·은행·계좌)이 바뀐 경우에만, 그리고 진행 중인 계약에만 반영합니다. 담당자 연락처를 고쳤다고 계약이 바뀌지 않습니다.
- **상태 악화 경고**: 거래중지·발주차단으로 바꿀 때, 진행 중 계약은 그대로 진행되고 새 지정만 막힌다는 것을 미리보기와 저장 결과 모두에서 알려 줍니다.
- **"반영"과 "연결"의 구분**: 값을 덮어쓰는 반영은 진행 중 계약만, 코드를 잇는 연결은 종료 계약까지 전부 대상으로 했습니다.
- **트랜잭션**: 마스터·계약·이력이 요청 트랜잭션 하나에서 처리돼, 중간 실패 시 함께 되돌아갑니다.

## 파일
```
db/supplierMaster.cds          엔티티(원장 · 변경 이력)
srv/supplierMasterService.cds  서비스 정의(함수 · 액션)
srv/supplierMasterService.js   권한 판정 · 오류 변환 · 감사 로그
srv/lib/supplierMaster.js      업무 로직(미리보기 · 저장 · 반영 · 연결)
```
