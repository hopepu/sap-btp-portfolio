# 빈 칸 정렬 유틸 — MutationObserver 성능 개선

모든 화면이 공통으로 쓰는 "빈 값 칸 가운데 정렬" 유틸입니다. 기능은 그대로 두고 **실행 비용만 줄인** 사례입니다.

## 문제
- 처음 버전은 변경 감시 콜백에서 바뀐 노드마다 `closest` / `querySelectorAll`을 즉시 실행했습니다.
- 큰 표(수천 행)를 다시 그리면 노드 수천 개마다 DOM 검색이 돌아, 한 화면에서 CPU를 1.6~2.1초 사용했습니다.

## 바꾼 방식
| 전 | 후 |
|---|---|
| 콜백 안에서 바뀐 노드마다 칸 검색 | 콜백은 바뀐 **요소만 Set에 모으기** |
| 변경마다 즉시 처리 | `requestAnimationFrame`으로 **다음 프레임에 한 번** 처리 |
| 안쪽·바깥쪽 요소를 각각 검색 | 바깥 요소가 함께 바뀌었으면 **안쪽은 건너뜀** |
| 모든 요소에서 칸 검색 | 안에 `<td>`가 없는 요소는 **검색 생략** |

## 결과
- 같은 화면에서 유틸이 쓰는 CPU 시간 **2.1초 → 0.02초**
- 칸 판정 결과는 이전과 동일(화면 비교로 확인)

## 교훈
"무엇을 하는지"보다 "언제·몇 번 하는지"가 성능을 좌우하는 경우가 많습니다. 변경 감시는 모으기(콜백)와 처리하기(프레임)를 분리하는 것이 기본입니다.
