# 2026-11 (1~6일)

## 공급업체 마스터 신규 구축
- 기획 TO-BE(PPT)를 바탕으로 CAP 엔티티(변경 이력 포함)·OData V4 서비스와 UI5 화면(왼쪽 목록 카드 + 오른쪽 상세 탭)을 새로 만들었습니다.
- 메뉴 등록, 역할별 메뉴 권한 부여까지 마치고 권한별로 실제 노출 여부를 확인했습니다.
- 기존 계약 데이터를 마스터에 연결하는 이관 액션을 만들고, 실행 후 연결 결과와 변경 이력을 검증했습니다.
- 매입계약 화면의 공급업체 칸 ↔ 마스터 연동을 끝까지 시험했고, 시험 중 바뀐 데이터는 원상 복구했습니다.

## 월마감 추정 입력
- TO-BE 설계를 바탕으로 월마감 추정 입력 화면을 개발했습니다.
- 과거 월마감 기간의 추정 데이터를 채워 넣는 스크립트를 만들고, 5년치 시험 데이터 재생성 후속 점검을 진행했습니다.

## 성능: 전체 메뉴 로딩 지연 개선
원인을 추측하지 않고 하나씩 측정한 뒤 제거했습니다.

| 원인 | 조치 | 결과 |
|---|---|---|
| 셸이 시작할 때 모든 화면을 붙잡는 느린 요청(최대 약 15초) | 화면 표시와 분리 | 진입 대기 제거 |
| 매입계약 표의 growing 렌더링으로 DOM이 수 MB까지 누적 | 렌더링 방식 수정 | 9.0s → 3.6s |
| 운전자금 현황이 같은 데이터를 수십 번 반복 조회(24회·80회) | 공유 키로 묶어 1회·8회로 축소 | 17.5s → 7.2s |
| 빈 셀 정렬 공용 유틸의 CPU 사용 | 판정 로직 개선 | 2.1s → 0.02s |
| Tailwind Play CDN 실행 시 컴파일 | 빌드된 CSS 파일로 전환, 8개 화면 픽셀 비교 | 회귀 없음 |
| CAP `$batch` 기본 병렬도 1 (요청이 순차 처리) | 병렬도 4로 상향 | 동시 처리 |

배포본 실측에서 매입계약 화면은 약 1.5초로 줄었습니다.

## 손익 흐름 전 기능 브라우저 시험
- 예산·채권/채무·경비 → 손익으로 이어지는 흐름을 10월 마감 시나리오로 끝까지 실행하고, 매출·원가 수치가 전표와 일치하는지 확인했습니다.
- 발견된 결함은 결정 사항을 정리해 처리했고, 시험 데이터는 백업 후 정리하는 스크립트로 되돌렸습니다.

## AI Office · Agentic AI 전수 점검
- 손익·예산·채권/채무·경비 × 콘솔·화면 AI·AI Office 조합으로 체크리스트를 만들었습니다.
- 수정 → 배포 → 재시험을 3회차까지 반복해 통과 항목을 늘렸습니다(1회차 104건 중 78건 → 3회차 92건 통과).
- 코드 점검 에이전트 4개와 브라우저 시험을 병행한 전수 점검으로 새 결함 65건을 찾아 41건을 수정했습니다.
- 지금까지 화면에 AI를 붙인 방식을 "화면 AI 시스템 구축 표준 절차" 문서로 정리했습니다(카드 = 업무 갈래 단위 에이전트, 자리 카탈로그 등록 → 출력 규칙 → 연결 순서).

## 손익 파이프라인 '담당 조직' 칸
- 파이프라인 데이터에 조직이 없어 프로젝트 기준으로만 조직을 도출하다 보니, 프로젝트가 없는 계약 전 건이 특정 조직에서 보이지 않았습니다.
- 영업 조직 칸을 추가하고 카드·상세·매트릭스 집계에서 담당 조직을 우선 쓰도록 바꿨습니다.
- 기존 데이터 약 5,900행은 백업·미리보기를 거친 백필 스크립트로 채웠습니다.

## 경영 분석 이상값 원인 분석
- 변동 배지가 비정상 값으로 표시되는 문제를 추적해, 계산 방식 불일치와 조직 매핑 변경이 겹친 것이 원인임을 확인했습니다.
- 오픈 일정을 고려해 수정은 보류하고 수정 순서만 정리해 두었습니다.
